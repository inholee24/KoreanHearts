```text

0x04  u16  레이아웃 수 n1        (0x10 부터 0x30 바이트씩; 창 위치·크기·색으로 보임 — 필드 의미는 추론)
```

### 문자열 디코더 `확정` (exe 0x258EB0 / 0x258F20, 2026-11-04)

- 0x80 이상 바이트는 **항상 2바이트** (Shift-JIS 계열 글자 또는 제어 `{F5}x` `{F6}x` 아이콘, `{F9}x` 색). 0x20 이하는 제어 (0x0A 줄바꿈).
- `{F9}x` 는 그리기 함수 0x25AF4F 에서 인자 'A'(0x41)~'I' 분기 표로 처리 (색 전환으로 추정). 원문 그대로 보존.

### 레이아웃 사각형 = 창 틀 크기 (exe + 데이터, 2026-11-05)

- 0x2B1563 이 위 필드를 읽어 창 생성 0x2B1F70 에 넘긴다 (줄 수 제한이 걸리면 높이 = max(h - 넘친 줄 x (크기+간격), 크기)). 0x2B1F70 은 창 틀 객체(0x90 B)를 이 위치·크기로 만든다.
- 글은 0x2B1D50 -> 0x25A380 (**글 크기 측정**: 최대 줄 폭·전체 높이·줄별 정렬 오프셋·줄 수) 으로 따로 잰다. 잰 크기로 창 틀을 키우는 경로는 찾지 못했다 (`추론`: 없음).
- 데이터: 메시지 1개짜리 레이아웃 1,302개에서 `w - 글 폭`(evt 폭 표 기준) p10 약 0 / p50 +18~24, 높이 1줄 30 / 2줄 52 / 3줄 76 -> **창 크기 = 원문 글 크기 + 여백으로 미리 정해 둔 값.**
- 그래서 번역이 원문보다 넓거나 줄이 많으면 창을 넘친다 -> 빌드가 레이아웃 크기를 늘린다 (`recom_layoutfix.py`, 아래 줄바꿈·창 폭 절).

### 글꼴 선택 `확정` (exe, 2026-11-04)

- 글꼴은 **텍스트 객체 플래그 [obj+0x40] 의 비트 12** 로만 정해진다 (0 = sysfont, 1 = evtfont). 그리기 0x25AA20, 0x25A380 이 `(flags >> 12) & 1` 로 글꼴 구조체를 고른다. 글꼴은 2개뿐.
- 텍스트 객체 생성자는 0x258BC0 하나 (직접 호출 4곳 + 감싸기 0x243F10 직접 호출 177곳, 함수 포인터 참조 없음). 생성 후 플래그를 바꾸는 코드 없음 (글꼴 모듈 안 검색).
- 비트 12 를 켜는 호출부: 0x102970 경유 14곳 (0x21000/0x21001, 호출 함수들은 0xF4000~0x101300 = 지미니 일지·카드 화면 코드: `card:%02d`, `jminy_chara`, `%s%02d.lad`), 0xFE680 (0x21002), 방 UI 0x117B40 (0x11202, `room01.lad`). **나머지 약 164곳은 sysfont.**
- 일본어 원본 CTD 대조 (`recom_fontuse.py`): 일부 WORLD 파일(02/1150, 03/2503~2505, 04/2100, 06/2504, 21/2000·2001·5010)의 한자는 일본어판 evtfont 표에만 모두 있다 -> evtfont 로 그려지는 텍스트 `추론`. WORLD03/0003 은 sysfont 표에만 모두 있다.
- **빌드 설계 결론:** 같은 코드를 두 글꼴 표에 각각 연결하고 모든 한글을 두 글꼴에 다 그리면, 어느 글꼴로 그려져도 맞다. 한글 종류 수가 sysfont 용량(963) 이내면 파일별 글꼴 판정이 필요 없다. 넘으면 그때 위 호출부를 기준으로 evtfont 전용 텍스트를 가른다.

### 줄바꿈·창 폭

- 그리기 함수(0x25AA20) 안에서 폭을 넘으면 줄을 바꾸는 코드는 찾지 못했다 (자동 줄바꿈 없음 `추론`, KH1 과 같음). 줄은 0x0A 로만 나뉘는 것으로 본다.
- 번역 줄 폭 규칙은 KH1 처럼 **원문 최대 줄 폭(같은 폭 표로 계산) 대비** 로 정한다 (단위 환산이 필요 없음). 도구 `recom_layoutwidth.py`.
- 그래도 넓어진 만큼은 빌드가 창을 늘린다 (`recom_layoutfix.fix`, 빌드·검증 공용): 레이아웃마다 Δ폭 = max(번역 최대 줄 폭 - 원문 최대 줄 폭) (sys/evt 큰 쪽, x 크기/칸), Δ줄 = 줄 수 차. w += ceil(Δ폭) (0.5 초과일 때, 짝수로), h += Δ줄 x (크기+1). 정렬 0 이면 오른쪽 끝 max(원래, 496)·아래 끝 max(원래, 440) 을 넘을 때 x·y 를 옮긴다. 줄이지는 않는다.
  2026-11-05 결과: 고유 레이아웃 183개 (파일 중복 포함 1,526) 커짐, Δ폭 중앙값 +9 / 최대 +38 px (1.28배), 높이 증가 8개, 위치 이동 2개. 화면 밖 0 (CT0002 L1 은 가운데 정렬이라 x 재계산).
  `recom_verify.py` 는 머리말·레이아웃이 "원본 + 이 규칙" 과 바이트 단위로 같은지 본다 (규칙 밖 변경 = 문제).

- 찾는 법: exe .rdata 의 NUL 끝 문자열 중 2바이트 기호(0x81~0x84)가 든 짧은 문자열 + 키보드 표. 디버그 문자열(일본어 문장)은 제외.

모자라면 드문 글자가 든 줄을 흔한 표현으로 고쳐 쓴다 (2026-11-09: 93줄, CTD 한글 951 -> 855).

코드는 한자 영역(0x88~0x9F, 0xE0~) 에 충분하다. 어느 화면이 어느 글꼴인지: 메뉴(FO0111 New Game 화면) = sysfont (확인). 대사·이벤트 = evtfont 로 추정 (미확인).

## 영상(이벤트 장면) 자막 MVS `확정` (2026-11-05)

- 파일: `remastered/FORM/5xxx/FO5xxx.BIN/<언어>_MVSnnn.binl` — UK 97개, 메시지 1,775 (고유 1,714, CTD 와 겹침 20). **이벤트 장면 대사 본편.**
- 형식 (5개 언어 x 97 파일 왕복 바이트 동일, `recom_mvs.py`):
  `+0 "MVS\0"  +4 u16 0  +6 u16 n  +8 u32 문자열 시작(0x30)  +0x10 항목 n x (u16 시작, u16 끝, u32 문자열 위치)`.
  문자열은 CTD 와 같은 인코딩, 0 끝, 4바이트 정렬(0), 파일 끝 0xCD 로 16 배수 (CTD 와 달리 0 4바이트 없음). 시각 단위는 미확인 (바꾸지 않음).
- exe: 이름 `MVS%03d` (0x60CEF0) -> 0x2993D0 (불러서 문자열 위치를 포인터로 바꿈), 0x299350 (찾기) <- 0x2994F0.
  자막 창 0x2995A0: 0x2B1420 (창 생성) 인자 = 위치 (0x30, y), 크기 416 x 46, 글자 크기 22, 정렬 2 (가운데), **플래그 0x300B**.
- **자막 글꼴 = evtfont** (확정): 0x2B1F70 이 글 플래그 = `(스타일==5 ? 0x2000 : 0) | (스타일!=3 ? 0x1000 : 0) | 인자 11` 을 만들고
  0x2B3AD0 -> 0x2B1D50 이 이 값을 글 객체 [obj+0x40] 에 쓴다. 자막 인자 11 = 0x300B (비트 12 켬). 그리기 0x25A380 이 `(flags >> 12) & 1` 로 글꼴 선택.
  (같은 경로로 스타일 3 이 아닌 CTD 창도 evtfont 다. 앞의 "글꼴 선택" 절의 생성자 플래그 조사는 생성 뒤 이 쓰기를 놓쳤다. CTD 는 계속 두 글꼴 모두에 넣는다.)
- 빌드: 자막에만 나오는 한글은 evtfont 에만 넣는다 (sysfont 963 칸 절약, evt 1,339 칸). verify 가 그런 글자가 CTD 에 없고 sysfont 표에 연결되지 않았는지 본다.
- 번역 폭 규칙 (`recom_tr.py`): 원문 대비가 아니라 고정 창 기준 — 줄 폭(evt 폭 표 x 22/26) <= 400 px, 줄 수 <= 2. 원문 자막: p99 377 / 최대 406 px, 1줄 904 / 2줄 808 / 3줄 1.

## 그림 IMGZ / IMGD (.imz) `확정` (2026-11-06, UK 257 장)

- `+0 "IMGZ"  +4 u32 0x100  +8 u32 0x10  +0xC u32 n  +0x10 (u32 위치, u32 길이) x n` -> 각각 `IMGD`.
- IMGD: `+8 u32 픽셀 위치(0x40)  +0xC u32 픽셀 길이  +0x10 u32 팔레트 위치  +0x14 u32 팔레트 길이(0)  +0x1C u16 폭, u16 높이  +0x32 u16 형식(19)`.
  형식 19 = 비압축 RGBA 32bpp, 선형(스위즐 없음), 알파 0~128. UK 전용 그림 목록·분류: [image-text.md](image-text.md).
- **PC 판 장치별 PNG `확정` (게임 확인 2026-11-09):** 같은 폴더에 `<언어>_<이름>_{other,ps,xbox}.png` (RGBA, 알파 0~255) 가 있으면 PC 판은 그것을 그린다.
  UK 에는 title (FO0505/FO0507), camp (FO0100) 만 있다. 타이틀 메뉴는 .imz 를 바꿔도 화면이 영어 그대로였고 PNG 를 바꾸니 바뀜.
  `UK_camp_other.png` 는 이름만 UK 이고 글자가 스페인어다 (원본 그대로 둠). `recom_imgtext` 가 .imz 와 같은 배치·글자인 PNG 에만 같은 작업을 그린다.
- **스프라이트 사각형 `.lad` `확정` (게임 확인 2026-11-09):** 게임은 .imz 를 통째로 그리지 않고 형제 폴더 `*.SPR/<같은 이름>.lad` 의 `SEQD` 표 사각형만 잘라 그린다.
  `LAYD` 파일 안 "SEQD" 위치 i: `+8 u32 개수, +0xC u32 표 위치(i 기준)`, 레코드 0x2C: `u32 ?, i32 x0, y0, x1, y1 (x1/y1 미포함), ...`.
  예: PAUSE 는 글자 5 칸 (4~50, 52~98, ... y 132~184). 칸을 넘는 글자는 잘리고 칸마다 다른 위치에 그려져 끊어진다. 여러 그림 .imz 의 텍스처 번호 필드는 미확인.
  새 글자는 사각형 안에 있어야 한다: `imgtext.json` 작업의 `box` (`recom_ladbox.py apply` 가 채움).
- 타이틀 메뉴 선택 줄: 게임이 회색 줄 글자를 검게 칠하고, 그림의 "속 빈 흰 테두리 글자"(회색 줄 + (0,264), BACK 은 (-512,198), 고리 폭 4px)를 그 위에 겹친다.
