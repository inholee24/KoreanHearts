# 알려진 문제와 미확인 항목

## 미확인

1. evtfont 칸 위치의 화면 확인 (그림 대조로는 맞음). evtfont 는 지미니 일지·카드 화면·방 UI 에서만 쓰인다 (exe, file-formats "글꼴 선택"). 모든 한글을 두 글꼴에 다 그리는 설계라 어느 화면이 어느 글꼴인지는 용량이 넘칠 때만 문제.
2. ~~한글 종류 수 <= sysfont 용량 963 인지~~ -> 해결됨 아래 참조 (2026-11-09: 용량 899, CTD 한글 855).
3. 레이아웃 +0x1A(창 폭으로 보임)의 단위, 자동 줄바꿈이 정말 없는지 (그리기 함수에서 못 찾음 = 추론). 번역 폭은 원문 대비 규칙으로 관리하므로 막히지 않음.
4. CTD 밖 텍스트: 영상 자막 (`FO5000.BIN` / `UK_MVS000.binl`), 카드 이름·설명, 방 카드, 층 이름 등.
5. 그림으로 된 글자 (타이틀 메뉴 NEW GAME/LOAD/THEATER/BACK 등, 카드 그림).
6. `{F5}`, `{F6}`, `{F9}` 제어 코드의 정확한 뜻 (번역 때 보존).
7. 타이틀 THEATER = 별도 Theater.exe 인지 (KH1 과 같다면 한글화 대상 아님).
8. SettingMenu(게임 설정) 는 KH1 에서 한글화한 공용 파일과 같은지.

## 해결됨

- 영어 모드가 읽는 텍스트: `remastered/.../UK_*.ctdl` (PoC 1).
- Panacea 적용 경로: `mod\recom\` + 추출 경로 (PoC 1).
- 영어 모드에서 2바이트 코드로 한글 표시 (PoC 2).
- **매핑·폭 표 `.binl` 교체 적용, 문자 코드 → 표 칸 공식, sysfont 칸 위치 (4쪽 x 25x12)** (PoC 3, exe 0x25C480 / 0x25C2DB). 한자 영역 코드(0x88~0x9F, 0xE0~)를 새 한글에 쓸 수 있다.
- 폭 표 구조: [0x10 + 글리프], 폭 1 = 2px.
- 한글 칸 용량: sysfont 963, evtfont 1,339. **2026-11-09 수정: 899 / 1,280** — 게임(exe)이 텍스트 파일 밖에서 그리는 글자(× → ☆★, 이름 입력 키보드의 악센트 문자·ASCII 기호)의 칸을 덮어쓰고 있었음 (덱 편집 "하03"). `recom_capacity.GAME_CODES` 로 지키고 verify 가 검사. 페이지 수는 exe 가 최대 4로 고정(0x25BDAF) -> 칸을 늘리지 않고 드문 글자 줄 93개를 고쳐 써서 CTD 한글 951 -> 855 (file-formats.md "게임이 텍스트 파일 밖에서 그리는 글자").
