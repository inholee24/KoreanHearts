## 2. 하지 말아야 할 시행착오

### 분석·판단

1. **추측 실험을 게임에서 반복하지 않는다.** 선택지 창 넘침에 폭 가설 H1(둘째 바이트), UI 표 +6(20차), evdl 사본(22차)을 차례로 게임에서 시험했고 사용자가 "창 크기 그대로" 를 세 번 보냈다. 답은 exe 의 스크립트 op4 즉값이었다. Re:COM PoC 3 에서도 같은 실수(게임 5회, 답은 exe 0x25C480). -> 예상과 다르면 분석으로 돌아간다.
2. **데이터 몇 개로 규칙 전체를 확정하지 않는다.** Re:COM 코드 공식(가나만 검증), sysfont 배치(왼쪽 위만 보고 25x25), KH1 "US 표 X/Y 는 아틀라스 좌표가 아니다"(knj0 와 비교한 오해) 모두 틀렸다.
3. **사용자가 보여 준 증거를 측정 없이 부정하지 않는다.** 말풍선 사다리꼴에서 "원래 연출" -> "패치 탓" -> "착시" 로 말을 바꾸다 사용자가 "같은 모양 아니라고. 옛날 스크린샷들이 내가 조작했다는거야?" 라고 했다. 해결은 **모드를 끈 원본을 같은 조건으로 측정**한 것. -> 먼저 측정하고, 결과를 수치로 보여 준다. 사용자 관찰을 "착시" 로 부르지 않는다.
4. **이름·사실을 기억으로 말하지 않는다.** 대기 영상을 "카이리의 편지" 라고 했다가 사용자가 KH2 영상이라고 정정. 영상·장면 이름은 데이터(영상 프레임, 대사)에서 확인한 것만.
5. **있는지 확인 안 한 UI 를 찾으라고 하지 않는다.** 설정 메뉴 시험에서 "Languages" 항목을 보라고 했으나 Steam 판에는 없었다 ("LANGUAGES는 어디있는건지 못찾겠어").
6. **어느 글꼴·경로로 그려지는지 먼저 확인하고 번역을 넣는다.** exchange 오프셋 표 파일을 대화창 글꼴로 넣었다가 월드맵·이름 입력이 깨졌고(38차, 보류), 지미니 메모를 시스템 글꼴로 넣었다가 글자가 바뀌어 나왔다(44차, 실제로는 대화창 글꼴). 0x1A 디코더 탓이라는 첫 진단도 틀렸다. -> 잘못 나온 글자를 두 글꼴의 같은 코드와 대조하면 어느 글꼴인지 바로 안다.
7. **화면 글자의 출처를 텍스트 검색으로 짐작하지 않는다.** PAUSE 를 sysmsg 94/471 로 고쳤으나 실제는 낱글자 메시지 4~8 이었다 (일시 정지 중 메모리 검색으로 찾음). 글자 사이를 제어 코드로 벌린 문자열은 일반 검색에 안 걸린다.
8. **요청의 목적을 넓게 오해하지 않는다.** "싹 다 분석" 은 실제 한글 글자를 불러오는 방법을 찾기 위한 것이었다. 애매하면 내가 이해한 목적을 한 줄로 밝히고 진행한다.
9. **사용자 지시를 기억에 옮길 때 뜻을 바꾸지 않는다.** "네가 직접 확인할 수 있을때까지 분석해" 를 "게임을 직접 켜라" 로 저장했다 (11-04 정정). 메모리에는 원문을 같이 적는다.

### 빌드·도구

10. **변경 수가 예상과 맞는지 본다.** recenter 부호 실수로 457개를 바꿈 (의도 107개). 빌드 출력의 "바뀐 수" 를 예측과 비교.
11. **배치 파일의 key 오타·잘못 섞인 줄** (b015, b017, b039) -> apply 가 key 존재·구조를 검사한다. 손으로 고친 뒤에도 verify.
12. **원본 크기·고정 버퍼 한도를 넘기지 않는다.** 고정 버퍼에 덮어쓰는 파일은 빌드가 크기를 검사 (OFS_LIMIT, kmb 한도).
13. **세션 임시 폴더에 재사용 스크립트를 두지 않는다** (10-28 전부 유실). 저장소 tools/ 와 docs 가 기준.
14. **ModsManager Build / Restore / Fast restore 금지** (mod 폴더 통째 삭제, 09-21).
15. 셸: heredoc 안 백슬래시(`\\n`, `\\x00`, `\2026` 8진수)가 바뀐다 -> 백슬래시 든 코드는 Write 로 파일을 만들어 실행. sed 대괄호 이스케이프 조용히 실패. CRLF 목록 비교 오탐. `cmp -l` 은 8진수. PowerShell 5.1 한글 파일명 깨짐. `python -I` 는 `-X utf8` 필요.
16. 게임 조작: Alt 로 포커스 -> 창 메뉴가 열림 (F24 사용). WM_SYSCOMMAND SC_CLOSE -> 종료 창. 런처 Enter 가 로고 중에 사라짐 (화면 확인 후 입력). 대기 상태처럼 타이밍에 민감한 화면에서 포커스 뺏기 금지. 실행 중 메모리 패치(tex2x)는 시간 제한·게임 재시작에 따라 다시 띄워야 했다.
17. **KH1 도구(kh1/tools)를 Re:COM 작업 때문에 고치지 않는다** (내용 해시가 바뀌면 KH1 사용자에게 업데이트가 뜬다).

## 3. 효과가 있었던 진행 방식

- 갈림길마다 **번호 붙은 선택지 + 추천 + 이유**. 사용자는 번호로 답한다.
- 실험 전에 **"화면 A 면 확정, B 면 기각" 표**를 적는다 (work-history 의 각 차수 표).
- 빌드마다 **백업 폴더 + SHA256SUMS + 새로 생긴 파일 목록** (`openkh_backups/<날짜>_testNN_before`). 되돌리기가 쉬웠다.
- 빌드 뒤 **verify 문제 0** 을 확인한 뒤 적용·보고.
- 처음부터 다시 만든 결과가 이전 결과와 **바이트 동일한지** 확인 (배포 파이프라인, 설치기 0.4.0).
- 보고는 **바꾼 것 / 확인한 것 / 확인 못 한 것 / 사용자가 할 일(있으면)** 을 나눠 짧게.
- 확인 못 한 장면은 known-issues 의 "유저 플레이로 확인할 것" 목록으로 남긴다.
