# KH1 exe 분석 자료

대상: `KINGDOM HEARTS FINAL MIX.exe` (Steam HD 1.5+2.5), sha256 `d790746245d26159f3ee0e1060e33b2fa2de06941850a4ac724f598722884bac`.
주소는 모두 **RVA** (ImageBase `0x140000000`, 실행 중에는 ASLR 로 모듈 베이스가 바뀐다).

`확정` = 디스어셈블 또는 실행 중 메모리로 확인. `추론` = 구조로 짐작.

## 4. 이벤트 스크립트 VM

**바이트코드 형식** `확정`: 명령 하나 = 4바이트 `[피연산자 24bit LE, 부호 있음][명령 번호 1B]`. 처리 표 `0x4E5DB0` (32개).

| 명령 | 의미 |
|---|---|
| `0x01` | ALU (`0x4FD850[피연산자]`: 0 add, 1 sub, 2 mul, 3 div, 4 mod, 5 neg, 6 eq, 7 gt, 8 ge, 9 lt, 10 le, 11 ne, 12 and, 13 or, 14 xor, 15 not, 16 sar, 17 shl) |
| `0x02` / `0x03` | jmp / jz (pc 는 4바이트 단위) |
| `0x06` | pop -> var |
| `0x09` | **push 즉값** (가장 흔함) |
| `0x0A` / `0x0B` | push local / pop local |
| `0x15` | push 즉값 (예외 처리 있는 판) |
| `0x18` | **네이티브 호출** `vm_op_table` `0x4FA870[피연산자]` (0~763) |
| `0x1E` / `0x1F` | 저장 플래그 비트 읽기 / 쓰기 |

네이티브 함수 인자는 스택에 push 한 순서대로 받는다. 예:

```
02 00 00 09 | 07 00 00 09 | 03 00 00 09 | 04 00 00 18
push 2        push 7        push 3        call op4      -> 템플릿 2 = 폭 7, 높이 3
```

**스크립트 위치** `확정`: 언어별 `remastered\<월드>.ard\<언어>_<월드>_ard<n>.evdl` (+ `.ev`). 원본 아카이브 `<월드>.ard` 에도 JP 기준 사본이 있다. 실행 중에는 언어별 `.evdl` 의 스크립트가 쓰인다 (트래버스 타운 상점: `UK_tw11_ard0/ard2.evdl`). 스크립트는 파일 안에서 4바이트 정렬이 아닐 수 있다.

## 5. 대화창 글꼴 텍스처와 용량 (2026-10-29)

언어 설정 `font_lang_setup` `0x18D130` `확정`:

| | 영어 등 | 일본어 (언어 ID 0, 7) |
|---|---|---|
| 페이지당 줄 `0x4DE830` | 16 | 21 |
| 줄 높이 `0x4DE834` (PS2 px) | 32 | 24 |
| 글자 수 `0x2340BA8` | 1344 (0x540) | 1764 (0x6E4) |
| 텍스처 크기 (`kanji_load`) | **512 x 512** | **1024 x 1024** (`+0x94/+0x96` x2, `0x1764B6`) |

- 셀: 열 21개 고정, 폭 24 px. `page = idx / (21 x 줄수)`. **페이지 비트0 -> U +512, 비트1 -> V +512** (`0x1762BB`). 텍스처는 페이지와 무관하게 하나다. 페이지 4 이상은 처리하지 않는다 `확정`.
- 그러므로 영어판의 페이지 1~3은 512 x 512 텍스처 밖을 가리켜 보이지 않는다.
- HD 교체: `tex_create_from_buf` `0x10BDF0` 가 버퍼의 파일 내 오프셋(`0x10DB60`)을 키로 `remastered\<파일>\` 의 DDS 를 찾는다. 등록은 `0xE1680` (이름 끝 16진 번호 = 키, 0 은 `0x10000000`). kanji_buf = 오프셋 0 = `UK_kanji_knj0.dds`. DDS 는 텍스처 전체 범위에 늘여 붙는다 (해상도 자유).
- 용량을 늘리는 후보 `추론`, 미검증:
  1. 영어에서도 텍스처를 1024 x 1024 로 (분기 `0x1764BD` 무력화, 또는 실행 중 `[0x22EC3C8]+0x94/+0x96` 쓰기) -> 페이지 1~3 = **1344칸**. **25차에서 확정** (실행 중 쓰기 `mem.py tex2x`, 2026-10-29).
  2. 일본어 배치(21줄 x 24 px)까지 쓰면 **1764칸** (`0x18D130` 의 영어 쪽 상수 변경, 폭 표 1764칸으로 확장).
  3. 상한: 2바이트 첫 바이트 `0x19`~`0x1F` -> idx 최대 2015. 단 `0x1A`(idx 480~735) 는 공백 처리되어 못 쓴다.
- 2번은 28차에서 실행 중 쓰기로 동작 확인 (`mem.py tex2x ... jp`).
- **화면 사각형 크기** (`kanji_cell_xy` `0x175FC4`~`0x17606A`) `확정`: 폭 = 크기 인자. 높이는 일본어면 크기 인자, 그 외 언어는 크기 == 20(대화창)이면 크기+8 = 28, 아니면 **그릴 때 `[0x4DE834]`** (`0x176021`, 장소 이름 등). 그래서 jp 배치(줄 높이 24)에서는 대화창은 28 그대로(셀을 세로 3/4 로 넣어 보정, 29차), 장소 이름은 24 로 눌린다 -> `0x176021` 을 32 상수로 패치 (32차).
- **msg_layout 제어 코드** (`0x1767B0`, 점프 표 `0x177640` = 코드 0x00~0x1F 핸들러) `확정`, 35차:
  - `0x0D` (`0x176D27`): `0D 00 lo hi` = 글자 표시 속도 (`[+0x20] = 128 / (hi<<8|lo)`), `0D 01 lo hi` = 페이드 시간. **배치(위치·폭)에 영향 없음.**
  - `0x0B` (`0x176C34`): x 위치 이동. `0B 00` 상대(+), `0B 01` 절대, `0B 10` 부호 있는 상대.
  - `0x02` (`0x176A82`): 줄바꿈. 현재 x 를 `line_width[]` 에 기록하고 x=0, y 는 `[0x2340BA0/A4]` 만큼 내림.
  - **자동 줄바꿈 없음**: 글자 경로(`0x176960`~)는 x 에 폭을 더할 뿐 한계와 비교하지 않는다. 줄은 `0x02` 로만 나뉜다. 창 크기는 최대 줄 폭에서 정해진다(`msg_get_size`).
  - 따라서 번역 줄이 원문 최대 줄 폭 이하이면 창이 원문보다 커지지 않는다.
- 줄 간격 `0x2340BA0` / `0x2340BA4` = 줄 높이 + 4 / + 13. 정적 초기화(`0x3830`/`0x3820`)에서 계산되고 일본어면 `0x18D130` 이 28/37 로 덮어쓴다.
- 대사에 시스템 TTF 를 쓰는 경로는 없다. HD판 `font/*.cod/.inf/.tm2`, GDI `CreateFontIndirectA` 는 설정 메뉴(SettingMenu)용.

## 5-1. UI(시스템) 글꼴 텍스처와 용량 (40차, 2026-10-29)

`확정`(디스어셈블) / `추론` 구분. 도구 `tools/sysfont.py`, 시뮬레이터 `tools/sysfont_sim.py`.

| 단계 | 위치 | 내용 |
|---|---|---|
| 표 적재 | `0x2D1570` | `exchange/US_font_data_tbl.bin` -> 정적 버퍼 `0x2E16BF0`, 포인터 `0x2E16BE0`. 버퍼 크기 **0x4000 = 1024 레코드** (다음 전역 `0x2E1ABF0` 은 별개 int). 원본 파일 560 레코드 `확정` |
| 디코드 | `0x2CFBF0` 외 5곳 | `<0x15` 제어, `0x18` 별도, `0x15~0x1F` 2바이트 `(b0<<8|b1)-0x1820`, `>=0x20` 1바이트. **0x1A 문제 없음** (대화창 `msg_layout` 과 다름) `확정` |
| 그리기 | `0x2CFBF0` | 소스 = (X, Y) ~ (X + 폭*16, Y + [0x545344]*16). [0x545344] = 24 (실행 중). `+7` -> GS TEX2: PSM = `0x52A6F8[+7>>4]` (0x24 4HL / 0x2C 4HH), CSA = `+7 & 0xF` `확정` |
| HD 변환 | `0x304483` | CSA==1 -> u += 0x1000, PSM==4HH -> v += 0x1000, 그 뒤 HD px = (2*값 - 8)/16. 즉 4페이지 = DDS 사분면 4개 (PS2 256 = HD 512) `확정` |
| 정규화 | `0x2D18F0`, `0x141FA1` | sysfont 텍스처 +0x94/+0x96(논리 크기) = +0x7C/+0x7E. +0x7C 는 HD DDS 실제 크기 (대화창 텍스처가 4096 DDS 에서 +0x7C=4096 인 것으로 확인). UV = HD px / 논리 크기 `추론`(대화창 tex2x 와 같은 원리) |

**용량:** DDS 를 2048 로 키우면 논리 크기도 2048 -> 원본 좌표는 왼쪽 위 1024 에 1:1, 레코드 X/Y(u16, 1/16 PS2px)로 확장 영역을 가리킬 수 있다. 레코드 수는 1024 가 한도 (넘으면 포인터 `0x2E16BE0` 를 메모리 패치로 옮겨야 함). 2바이트 둘째 바이트 00/04 를 빼면 한글 칸 710 (제자리 가나·빈칸 250 + 새 레코드 460).

**정렬·제어 (41차 `확정`):** 그리기 `0x2CFBF0` 의 정렬 모드는 호출 인자, 제어 `0x04` 왼쪽 / `0x05` 오른쪽 / `0x06` 가운데. 오른쪽·가운데는 측정 `0x2D0E10` (줄 끝 00/02/03 까지 폭) 으로 시작 x 를 정한다. `0x0C n` 크기(n/24 배), `0x0D lo hi` x 이동 (그리기는 배율 없음, 측정은 n/24 배 -> 가운데 정렬 문자열에서 차이 남), `0x0E lo hi` y 이동, `0x01` 공백 (`0x2E954F0` = 5, 크기 배). 글자 간격 전역 `0x2E16BEC` = 0. evmsg 표기는 0x0D/0x0E 를 대화창 길이로 잘라 보이므로 넷째 바이트가 실제 글자일 수 있다.

**메뉴 문자열 (42차 `확정`):** `0x28f9d0` 이 btltbl.bin 을 `0x2d22d40` 에 적재하고, HD 자산 목록(`0xe2b20` -> +0x670 연결 목록, 노드 +0x10 이름, +0x60 데이터)에서 `Word.bin`, `ItemHelp.bin`, `AbilityHelp.bin`, `AbilityName.bin` 을 찾아 `0x28f820`(다음 문자열) 으로 순서대로 넘기며 `0x38ad90`(포인터 -> 32비트 핸들) 결과를 표에 쓴다. 대화창 `0x0E xx` 핸들러 `0x176df3` 는 이 문자열(아이템 이름 `0x28f9b0`, 어빌리티 이름 `0x28f8f0`+`0x38adc0`)을 대화창 글꼴로 끼워 넣는다.

**표 확장 (43차 `확정`):** 정적 버퍼 0x2E16BF0 을 쓰는 곳은 font_tbl_init 뿐, 글자 그리기·측정·Shift-JIS 찾기(0x2d0400, 0x2d12e0, 0x2d19a0, 0x2d2bd3, 0x2d3340 등)는 모두 포인터 0x2E16BE0 을 거친다. Shift-JIS 찾기 수 0x2E16BE8 = 실행 중 560 (0x2e99b7 이 0x545348 에 0x230 을 쓰고 font_tbl_init 이 복사). mem.py tex2x 가 전체 표를 새 버퍼에 올리고 포인터·수를 바꾼다.
